# 调研简报：片源与媒体库都是"题材 → 女优 → 影片"三层结构（2026-11-10）

**结论先行**：CineSort 的"一个顶层目录 = 一部影片"单元契约（决策 D-20261031-05）与这批数据的真实组织方式不匹配。真实结构是三层，源根和库根**同构**。这解释了 owner 最初的抱怨"太多兜底和单项命中，和实际片源不符合"，也决定了剩余卡该不该继续做。

## 一、实测结构（递归探针，非推断）

源根 `E:\已刮削\待整理`：

```
待整理\<女优名 或 "#未知女优"/"未知演员">\<番号>\{1 个视频 + 1 个 NFO + 海报/字幕}
```

- 43 个被 scanner 判为"复合目录"的顶层目录，内含 **148 个内层目录**；
- 其中 **147 个各恰含 1 个视频**、**145 个自带 NFO**；
- 顶层目录根下直接躺着的视频 **0 个**。

库根 `E:\已刮削\<题材库>` 同构，实测抽样：

```
E:\已刮削\按摩\一乃あおい\JUR-439-C\…
E:\已刮削\按摩\#未知女优\…
E:\已刮削\合集长篇\JULIA\…
```

即：**每个题材库下面已经有一层女优目录**，影片目录住在第三层。

`py -3.12 -m pytest tests -q` → 259 passed；全仓 ruff 10 项（基线持平）。真实数据只读自检（主审独立复跑，与执行者输出一致）：

门禁有效（复合单元零默认勾选、零 ready）。但 **22 个同名冲突**暴露了新问题：

| 冲突例 | 目标路径 | 实质 |
|---|---|---|
| `#未知女优`（GOV-004 等） | `E:\已刮削\合集长篇\#未知女优` | 库里**已有同名女优目录** |
| `一乃あおい`（JUR-568） | `E:\已刮削\按摩\一乃あおい` | 库里已有 `按摩\一乃あおい\JUR-439-C` |
| `伊藤舞雪`（CAWD-876） | `E:\已刮削\按摩\伊藤舞雪` | 同上 |

22 个冲突里 **12 个是普通影片单元**（非复合）。它们不是"库里已有同一部影片"，而是**女优层目录撞名**——`on_conflict = skip` 于是把它们当冲突跳过。也就是说：**12 部本来能自动归位的片子，因为工具不懂女优层而被卡住。**

## 三、两条可选路径

**A. 嵌套影片目录识别 + 保留女优层**（证据更支持）

- scanner：顶层目录内若存在"自带 NFO 且恰含 1 视频"的内层目录，则每个内层目录成为一个单元；
- planner：目标路径组合改为 `库\<女优>\<影片>`，**同名女优目录合并**（已存在就往里放），不再当冲突；
- 收益：145 个内层目录自带 NFO 与题材标签 → 56 条 alias 直接命中 → 自动归位，无需猜、无需标题评分、无需 43 次人工改判；
- 代价：改动单元识别与 dst 组合契约（触及 D-20261031-05 / D-20261031-04），需要新规格 + decision-critic 评议 + 新计划；已合入的 C8/C9 不白做（复合判定与 ST_BATCH 仍在，只是命中面变小）。

**B. 维持现计划**（整目录单元 + ST_BATCH + 目录级批量改判）

- 43 次人工决策；但 22 个同名冲突必须先解决（改名或合并女优目录），否则**连人工改判也无法执行**（目标位置已存在同名目录）；
- 且把一个装 2–43 部影片的目录归给单一题材库，对女优目录本身是合理的（同一女优常跨题材），对"按题材归位"这个目标则偏粗。

## 四、我的建议

走 **A**，并把 B 的 ST_BATCH 保留为"真正混合目录"（内层不是完整影片目录的那些）的兜底。A 落地后，owner 最初抱怨的兜底与误判问题大部分会自然消失，而 B 单独存在无法解决那 22 个撞名。

## 五、未决问题（需 owner 拍板，不可由执行者自行决定）

2. 撞名时的语义：合并进已存在的女优目录（新语义），还是继续 skip？
3. 剩余卡 Task-11/12/13（执行链放行、整目录批量改判 UI、收口）是照原计划做完，还是先做 A 的规格与计划、把 11/12 押后？
